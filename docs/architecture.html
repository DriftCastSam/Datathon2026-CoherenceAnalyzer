Two features, coherence analysis and auto-explanation, run as one scripted AWS Step Functions state machine. Bedrock is called at five fixed points, each with a forced tool schema. The model never chooses the next step, never sets a limit and never writes a number we did not compute.

Feature 1

Coherence analysis: the LLM can only add warnings

The analysis has two lanes that meet only at the verdict. The rule lane computes limits and hard checks from user-declared values and rule: fields. The LLM lane reads behaviour, questions and free-text values, passes the gate, and feeds soft checks. Its strongest possible effect is a warning. A violation can only come from the rule lane.

Rule lane

  • derive → limits → H1–H14: pure functions, registered with their input paths.
  • test_limits_no_llm_inputs walks the registry and fails if any llm: path reaches limits.
  • N3 rules enter limits only after the user approves them, which makes them user-declared.

LLM lane

  • N1, N2, N3 run in a Parallel state. A branch is skipped when its input hash is unchanged.
  • The gate keeps the old value on abstain and rejects the whole output if one cited event_id or quote doesn't exist.
  • Soft checks run only when confidence ≥ 0.5. Otherwise they report info "insufficient evidence".
Feature 2

Auto-explanation: worst case is a deterministic template

The explainer sees only the facts payload, never the raw profile. Numbers arrive pre-formatted ("vol_pct": "7.4 %"), so the model copies them and never computes. Post-checks are code. If they fail twice, the template writes the explanation from the same checks. Each report records which path it took in explanation.mode.

The five LLM nodes

All five use llm/bedrock.call_tool: Converse with one toolSpec, toolChoice forced to that tool, temperature 0, jsonschema validation with one retry, and a cache keyed by sha256(node, prompt_version, model_id, payload).

Where variance can enter and what pins it

Determinism, layer by layer

Temperature 0 makes Bedrock output stable, not bit-exact. Reproducibility comes from the cache: a recorded response is replayed exactly, and PORTEE_LLM=mock runs the full pipeline from fixtures/llm_cache/ with no network.

Which Bedrock product

Why Step Functions + Converse instead of Bedrock Agents

OptionWho decides the next stepFit for Portée
Step Functions + Converse recommendedOur ASLMatches SPEC "scripted DAG". The local pipeline and the cloud share one Python package, and mock mode works unchanged. The diagram is already planned for the video (SPEC §17 step 15).
Bedrock Flows alternativeOur flow graph (prompt, Lambda, condition, iterator/collector, inline-code nodes)Also a fixed DAG, so it would work for the explanation subgraph. Keep the gate and numcheck in Lambda nodes. Before choosing it, check that a prompt node can force a tool schema on our model. If it can't, call Converse from a Lambda node, which gives the Step Functions design again.
Bedrock Agents (InvokeAgent) not for the coreThe model, via its orchestration loop over action groupsThe same input can take different paths, which conflicts with invariant 8. Return-of-control only hands execution back to the app. The model still picks the action. Possible later for a free-text intake front-end, never for checks or limits.
