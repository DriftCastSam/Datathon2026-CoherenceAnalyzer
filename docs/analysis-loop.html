The analysis loop: profile vs portfolio

How CoherenceAnalyzer measures the gap between an investor's own profile and their portfolio, or a trade they propose (Flow B, pipeline.check). It is a scripted DAG, not a free-roaming agent: code owns every limit and every verdict, and the LLM (Bedrock, forced tool use) fills narrow slots that a deterministic gate or verifier checks before anything is used.

user-declared deterministic rule / engine LLM node (Bedrock) gate / verifier template fallback

1. The pipeline (B1 to B9)

B1 · N4 intent_parser

Parse the trade

"10% NVDA" → draft intent. Ticker must be in the universe enum; ambiguous fields are listed, never guessed.

B2 · confirm

User confirms

The confirmed intent is user data. The draft only prefills the form. Nothing auto-executes.

B3 · Flow A refresh

Rebuild the profile

Derive horizon, capacity, effective risk → limits + trace. N1/N3 run here, but only through the gate.

B4 · intent.apply

Proposed portfolio

Apply the user's own funding to the current weights.

B5 · engine

Analyse both sides

Vol, max drawdown, P5 at horizon, goal probs. Same seed, same horizon, current vs proposed.

B6 · checks + diff

Measure the gap

Hard checks H1–H14 (can be violation), soft S1–S4 (warning at most). Verdict + diff.

B7 · resizer

Headroom

If the trade adds a violation: scan + binary search for how far this trade goes before it crosses a limit.

B8 · N5 explainer loop

Explain, verified

Five factor sections narrated in parallel lanes + N6 consistency. See section 2.

B9 · save

Report + audit

Every LLM call logged with model, prompt version, input hash and its gate decision.

2. The inner loop: generate → verify → retry once → template

Per non-pass section (explain.narrate_section). At most two LLM calls; output that failed verification is never shown.

Facts payload

  • Only the section's non-pass checks, metrics, diff, headroom, unknowns, evidence events
  • Numbers pre-formatted ("7.4 %") so the model copies, never computes
  • The LLM sees nothing else
→

N5 explainer

  • Bedrock Converse, forced tool use, temperature 0
  • Segments tagged fact | assumption | inference | unknown, each with refs
  • Optional Guardrail: no personalised recommendations
→

Verifier V1–V5

  • V1 every ref resolves (check id, key path, event_id)
  • V2 numcheck: every number exists in the facts
  • V3 every violation/warning is cited
  • V4 advisory blocklist FR+EN ("you could", "rééquilibr", "next step"…)
  • V5 schema, kinds, lengths; inference only if backed by LLM field/evidence
↺ Fail on attempt 1: call N5 again with the list of failures appended. Fail on attempt 2, cache miss, or Guardrail block: deterministic template_section (always passes V1–V5).

5. The invariants the loop is built around

limits come from rule: fields and user-declared values only (test: tests/profile/test_limits_no_llm_inputs.py).
Only hard checks produce violation. LLM-derived checks: warning, info or unknown.
Describe, never prescribe: no trade, ticker, size or "next step" the user did not state. The headroom is the only trade figure, and it's template text.
Reproducible: cache keyed on node + prompt version + model + payload hash; COHERENCE_ANALYZER_LLM=mock replays offline.
